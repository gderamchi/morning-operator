# Native integrations for an ordinary iPhone

Research checked **15 October 2026**, against Apple and provider documentation. Product constraint: an App Store installation on a normal iPhone, with normal permissions and account authorization; **no Mac, Developer Mode, XCTest or supervised-device setup during use**. This is the research baseline and a feasibility map, not a device-test report. The subsequent implemented three-route slice and its proof boundaries are in [CONNECTIONS.md](CONNECTIONS.md).

The integration target is usually a shared data store or a service, rather than another app's interface. EventKit can change a calendar event without opening Calendar; a Gmail API request can act on the same mailbox shown in Mail. Being an Apple app does not imply that every feature has a public SDK, but public APIs and user-installed Shortcuts together expose substantially more than the current MORE implementation.

## The discovery that changes the assessment

Apple added Shortcuts **Find Message** for Mail, and **Find Message / Find Conversation** for Messages in iOS 26. iOS 27 extends messaging actions and introduces notification-triggered automations. Earlier statements that native Mail/Messages have no possible reading route were too broad: no general inbox SDK does not mean no Shortcuts route. [iOS 26 actions](https://support.apple.com/en-us/125148), [iOS 27 actions, published 29 September 2026](https://support.apple.com/en-us/149045).

The release notes establish that actions exist. They do **not** establish which fields, attachments, historical coverage, counts or account scopes they return to MORE, nor how they behave while locked. Those are the first normal-use experiments to run.

## Routes and what connection means

| Route | User setup | What MORE can reasonably promise after implementation |
|---|---|---|
| Native system API | Permission, and sometimes selected calendars, contacts or data types | Execute the operations exposed by that framework within the authorized scope. No need to open the Apple app. |
| Parameterized Shortcut | Add a supplied shortcut, choose its accounts/options and authorize its actions | Run a known workflow with input and collect a bounded result. Shortcuts or a target app may appear; some actions need interaction/unlock. |
| Provider API | Authorize the actual service account using an approved authentication flow | Read or change that service's data according to granted scopes. Does not depend on its native app being installed. |
| Website / Safari extension | Sign in and allow relevant website access | Supported web operations, subject to the site's permission and actual functionality. Separate session from the native app. |
| Share extension / selected file / deep link | Share or select content, or follow a destination link | Receive deliberately selected context, or hand off an action. A link opening successfully is not proof an external effect completed. |

An Apple permission, a provider OAuth grant and a manually marked-ready website are different connection states. Store operation-level capability and actual verification, rather than one generic “connected” flag.

### A concrete bridge to prototype

Proposed flow: **MORE request → installed, parameterized Shortcut → Apple action → structured result to a MORE App Intent → local review/action policy**. This is an implementation proposal inferred from the documented primitives, not a completed integration.

- Use the documented URL scheme to run an already-added shortcut with input; use the x-callback route for success/error/cancel. The URL handoff may show Shortcuts. [Run](https://support.apple.com/guide/shortcuts/apd624386f42/ios), [callbacks](https://support.apple.com/guide/shortcuts/apdcd7f20a6f/ios).
- Supply small versioned shortcuts or a fixed dispatcher with allowed operations. The user adds them and grants their permissions. No silent shortcut installation, arbitrary intent discovery or private workflow format is assumed. [Sharing](https://support.apple.com/guide/shortcuts/apdf01f8c054/ios).
- Add an app-owned result-ingestion action for structured fields; prefer that to placing private message bodies or tokens in callback URLs. The current capture action opens reviewed capture and is not an existing query-result transport.
- Correlate each result with its requested operation/session, expiry and data generation; validate incoming data. A callback must not itself authorize a new send/delete operation. Re-read an external effect where possible; reconcile ambiguous effects before retrying.
- Keep inference local. A Shortcut's cloud/ChatGPT `Use Model` option must not become a silent fallback. Ordinary system actions do not require Siri AI; do not make France availability depend on its current EU restrictions.

App Intents is not a generic command bus for MORE. Apple describes the cross-app orchestrator as a system capability; data publication does not grant another app arbitrary access. iOS 27 `RunSystemShortcutIntent` is explicitly restricted to widget buttons, so invoking it in the agent is not a substitute for this bridge. [Apple's orchestrator explanation](https://developer.apple.com/videos/play/wwdc2026/8011/?time=498), [widget restriction](https://developer.apple.com/documentation/appintents/runsystemshortcutintent).

| Outlook / Microsoft 365 | Delegated Microsoft Graph access to mailbox read/write and separate send permission. | SMS / MMS / RCS | TelephonyMessagingKit lets a genuine default carrier-messaging app send/receive. Customer conditions include EU account/device location. | WhatsApp Business | Business Platform offers a separate business messaging channel. Use `ASWebAuthenticationSession` or the provider's supported SDK for OAuth, then keep tokens in Keychain and process responses locally. Google's authorization policy excludes a generic embedded WKWebView. Browser sign-in alone does not authorize a provider API. [Apple authentication session](https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession), [Google native OAuth](https://developers.google.com/identity/protocols/oauth2/native-app).

## Other useful fallbacks

- **Share extension:** accept chosen text, links, documents or recordings from apps that expose sharing. This can supply context without global store access. It needs a new MORE extension and deliberate user sharing; it is not background ingestion. [Share extensions](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Share.html).
- **Safari web extension:** normal App Store distribution; user enables it and grants site access. Can read/modify allowed pages and exchange selected data with MORE. This complements the in-app browser when a site works better in Safari; it does not grant access to native app data or an unlimited background process. [Permissions](https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions), [distribution](https://developer.apple.com/documentation/safariservices/safari-web-extensions).
- **Permitted feeds / provider APIs:** useful for news, podcasts and other content without depending on a particular native app's private library. Preserve attribution, subscription/access rights and the distinction from the user's app history.
- **A chosen workspace folder:** a durable, ordinary-user way to let MORE create and organize files while keeping other app containers outside scope. This is more capable than repeated one-file import.

Other Apple app names also need a scoped claim:

| App | Route established by the reviewed documentation | What this does not establish |
|---|---|---|
| Safari | Add URLs to Reading List with `SSReadingList`; selected-site work through the extension route above. [Reading List](https://developer.apple.com/documentation/safariservices/ssreadinglist). | A complete Safari history/bookmark database connector. |
| Wallet | PassKit returns passes available under the app's entitlements. [Pass scope](https://developer.apple.com/documentation/passkit/pkpasslibrary/passes()). | Unrestricted access to every Wallet pass, financial account or payment capability. |
| Passwords | System credential authorization/AutoFill can assist an explicit sign-in. [Credential requests](https://developer.apple.com/documentation/authenticationservices/asauthorizationpasswordprovider). | A general Passwords-vault import or a substitute for the target service's authorization. |
| Find My | Apple's published developer program connects accessories through MFi. [Program](https://developer.apple.com/find-my/). | Access to all the person's devices, people and locations; no such general connector was established here. |

Books/news and other private libraries can use selected files, shared links or permitted feeds when available. Treat those as explicitly imported context or a separate content service, not a replica of the native app's complete library.

## Execution and distribution limits

Standalone does not mean constantly running. Background refresh is scheduled by iOS; an earliest start is not a guaranteed execution time. Continued processing can finish an explicitly user-started foreground job after backgrounding. iOS 27 `LongRunningIntent` adds progress/cancellation for longer intent work, not an unlimited daemon. Use user-started runs and configured event automations; test locked-device data availability separately. [Scheduling](https://developer.apple.com/documentation/backgroundtasks/bgtaskrequest/earliestbegindate), [continued processing](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados), [long-running intents](https://developer.apple.com/documentation/appintents/longrunningintent).

Public API availability is not approval of a particular integration. The mainstream release needs the relevant distribution capabilities, the intended use of each framework, permitted third-party access and appropriate data handling. The existing web experiments do not establish service permission or App Store approval. [Review rules 2.5.1, 2.5.4 and 5.2.2](https://developer.apple.com/app-store/review/guidelines/), [current web evidence](IN-APP-BROWSER.md).

`UserNotifications` reads MORE's own delivered notifications. The new notification Shortcut is a separate potential event bridge. `AccessoryNotifications` is for real accessory companion products with its own EU conditions; it is not a standalone-app workaround. [Own notifications](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/getdeliverednotifications(completionhandler:)), [accessory framework](https://developer.apple.com/documentation/accessorynotifications).

## Recommended next proofs

1. **Mail + Messages read bridge:** install a small shortcut through ordinary user setup on an iOS 27 phone. Search harmless, known test items and return bounded fields into MORE. Record the exact account/history scope, first/repeated permission prompts, cancellation and locked behavior. If fields or return transport are missing, retain that failure rather than inventing a count.
2. **Notes + Clock bridge:** read one selected note and existing alarm. Then deliberately create a disposable note/alarm, verify it in the native app and remove it. This distinguishes working operations from a successful handoff.
3. **Notification event bridge:** test one innocuous selected-app notification, including hidden preview and locked conditions. Establish the payload MORE actually receives and deduplicate repeated events.
4. **Complete existing direct adapters:** connect reminder reads to the briefing; expose controlled Calendar/Reminders update/complete/delete operations. Add Contacts and a selected workspace folder according to the chosen morning tasks.
5. **Provider and optional native adapters:** one Gmail/Graph OAuth round trip first; MusicKit, HomeKit and HealthKit according to actual user needs. Treat default carrier/dialer roles as separate entitlement/product spikes.

For each proof, report installed OS/app, route, permissions/scope, actual returned data, action receipt/readback and foreground/locked result. No new phone action, account authorization, external send, deletion, entitlement grant or App Store validation was performed during this research. Documentation-only changes do not establish runtime success.
